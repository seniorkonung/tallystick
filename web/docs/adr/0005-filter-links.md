# Фильтры целиком в ссылке на них

Ссылка на фильтры живёт в текстах записей и в сообщениях чатов: её копирует
пользователь из шторки фильтров и ассистент из результата поиска. Ссылка хранит
фильтры целиком — `filter:` и JSON фильтров в base64url. JSON канонический:
постоянный порядок ключей, отсортированные id типов и тегов, без значений по
умолчанию и без случайных id условий, поэтому одинаковые фильтры дают одинаковую
ссылку. Ссылку кодирует приложение, а не модель: модель копирует готовую ссылку из
ответа `search_entries`. Фильтры в ссылке и на входе `search_entries` описывает одна
схема, и открываемая ссылка проверяется ею.

## Рассмотренные варианты

- **Ссылка на сохранённый набор фильтров по id**, как ссылка на запись. Короче
  в тексте, но добавляет таблицу, которую надо хранить и чистить, а ассистенту —
  отдельный инструмент создания ссылок.
- **Читаемый вид, например `filter:tag=…&last=7d`.** Понятен модели и человеку
  в поле ввода, но условиям по полям нужен свой синтаксис, а пробелы и скобки
  ломают разбор ссылки в тексте.

## Последствия

- Ссылки хранятся в текстах, поэтому формат фильтров меняется только совместимо:
  новый фильтр получает значение по умолчанию (`normalizeFilters`), а переименование
  ключа требует миграции текстов записей и сообщений чатов, как было с пресетами.
- В поле ввода код ссылки нечитаем, обычно 100–250 символов; в ленте видна только
  подпись.
- Модель код не читает: ссылку из сообщения или записи она передаёт в
  `search_entries` и получает её фильтры обратно.
