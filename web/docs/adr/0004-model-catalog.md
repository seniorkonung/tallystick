# Сведения о моделях из каталога models.dev

Чату нужны окно контекста модели, её понятное название и поддерживаемые уровни
размышлений. AI SDK их не сообщает, а API провайдеров отдают их по-разному или
не отдают вовсе. Разведчик берёт их из открытого каталога models.dev: каталог
доступен из браузера и описывает модели сотен провайдеров. Модель ищется по
названию без вендора, а не по адресу провайдера: свой совместимый API может
отдавать любые модели. Одна модель есть у многих хостов, поэтому берётся
значение большинства. Сведения о модели не меняются, поэтому каталог
скачивается, только когда о какой-то модели из списков провайдеров их ещё нет,
и в IndexedDB сохраняются сведения только об этих моделях.

Занятый контекст каталог не даёт: его сообщает провайдер в каждом ответе, и AI
SDK отдаёт эти числа одинаково для всех провайдеров.

## Рассмотренные варианты

- **Таблица моделей в коде**, как у paseo для Claude. Устаревает с каждой новой
  моделью и не покрывает совместимые API.
- **Список моделей из API провайдера.** Anthropic отдаёт окно, OpenRouter тоже,
  но OpenAI и большинство совместимых API — только идентификаторы.
- **Окно, вписанное пользователем.** Точно, но требует ручной работы для
  каждой модели.

## Последствия

- Модели, которой нет в каталоге, показываются идентификатором, с занятым
  контекстом без окна и со всеми уровнями размышлений. Такая модель ищется в
  каталоге снова не чаще раза в неделю: новые модели появляются в нём с задержкой.
- Если свой API урезает окно и не сообщает об этом, показывается полное окно
  модели; о переполнении говорит ошибка провайдера.
