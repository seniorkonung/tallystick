# Tallystick

## Проблема

Обычные заметки трудно организовать, а там, где организация сложна, записи
перестают вестись. Мессенджер решает запись: одна лента, пишешь не задумываясь.
Но в нём нет навигации: к записям не вернуться, их не отфильтровать, не разделить
по направлениям, а разнос по разным чатам — та же сложная организация.

Tallystick — одна лента всего, что записывается: мысли, еда, тренировки, заметки
по проектам. Поверх неё — лёгкая организация (типы, поля, теги) и быстрая
гибкая навигация по всему этому.

## Для кого

Сейчас — для автора. Позже — для других людей. Решения принимаются по опыту
автора, не по воображаемому среднему пользователю.

## Принципы

- Записывать много и быстро, не задумываясь об организации. Скорость записи
  важнее структуры.
- Организация простая и необязательная в момент записи: тип, поля и теги
  можно указать или изменить в любое время.
- Лента одна. Разделение записей — только фильтрами.
- Локальное приложение в первую очередь: работает на устройстве, без сервера
  и аккаунта. Исключение — чат: ассистенту нужен внешний провайдер.

## Чего продукт не делает

- Не задачник: нет сроков, напоминаний и отметок «выполнено».
- Нет системных типов: все типы создаёт пользователь.
- Нет нескольких лент.
- Время записи нельзя изменить.

## Продуктовые решения

### Лента и записи

- Лента упорядочена строго по времени добавления записи; это время неизменно.
- Запись: текст, вложения (фото, видео, файлы), значения полей своего типа,
  теги, ответ на другую запись, актуальность.
- Неактуальная запись остаётся в ленте, но помечена; скрыть её можно только
  явным фильтром.
- Запись можно удалить безвозвратно, вместе с её вложениями. Ответы на неё
  остаются в ленте с пометкой «Запись удалена» вместо цитаты.
- Текст записи форматируется маркерами, как в Телеграме: жирный, курсив,
  зачёркнутый, моноширинный, блок кода, цитата, скрытый текст и ссылка
  с текстом вместо адреса. В поле ввода видны маркеры, в ленте — оформление;
  выделение текста открывает панель, которая расставляет маркеры. Ссылки
  распознаются и без протокола.

### Типы и поля

- У записи ровно один тип. При первом запуске есть один тип по умолчанию без
  полей; его можно править и удалять, но хотя бы один тип есть всегда.
- Виды полей: один из списка, несколько из списка, число, строка, дата, дата
  и время, время. Единицы измерения у числа нет; дата — день без времени,
  дата и время — местное время. Все поля необязательны.
- При смене типа записи значения полей, которых нет в новом типе, теряются —
  после предупреждения.
- При удалении типа его записи переводятся в выбранный пользователем другой тип.
- Типов может быть много, поэтому выбор типа двухуровневый: сначала избранные
  типы без поиска для быстрого выбора, затем все типы с поиском, где тип
  отмечают избранным. Пока избранных нет, сразу открываются все типы.

### Теги

- Тег — пометка, которой пользователь группирует записи по любому признаку:
  теме, направлению, проекту. Это привычнее, чем «проект»: использовать тег как
  проект — соглашение самого пользователя. У записи может быть несколько тегов.
- Тег активен или в архиве. Дата ухода в архив ставится автоматически, по ней
  видно, что тег больше не используется. Даты начала у тега нет: важно, когда
  тег закончился, а начало видно по первой записи с ним.
- Привязка записи к тегу в архиве автоматически возвращает его из архива; дата
  ухода в архив при этом стирается.
- Уход тега в архив и возвращение из архива отмечаются в ленте служебными
  отметками. Создание тега в ленте не отмечается.
- Активных тегов много, поэтому они разложены по категориям, как папки
  в Телеграме. У тега одна категория; при уходе в архив она замораживается,
  при возвращении тег возвращается в неё.

### Ответы

- Ответ — запись, привязанная к исходной записи. Под записью видны только её
  прямые ответы.
- Ответы на запись — та же хронология, ограниченная прямыми ответами на неё.
- В общей ленте ответ виден на своём месте с цитатой исходной записи.

### Навигация

- Ядро: фильтры (тип, тег, актуальность, период), поиск по тексту и условия
  по значениям полей.
- Ответы можно скрыть фильтром: в ленте остаются записи, которые сами не ответы,
  и через них открываются их ответы. Фильтра «только ответы» нет — сценария для
  него не нашлось.
- В фильтре по тегам есть вариант «Без тегов»: он выбирается вместе с тегами
  и добавляет к их записям записи без тегов.
- Статистика показывает, сколько записей создано за неделю, месяц или год;
  периоды листаются назад. Основной режим — по тегам: у каждого тега, включая
  теги в архиве, число записей, доля от всех записей периода и разбивка по
  типам; записи без тегов идут отдельной строкой. Дополнительный режим — по
  типам, без тегов. Нажатие на элемент статистики открывает ленту с его
  фильтрами: периодом, тегом и типом.
- Статистику по тегам можно ограничить категориями тегов, чтобы скрыть
  ненужные для неё теги; среди вариантов есть «Без категории». Выбор
  запоминается. Итог и доли тегов по-прежнему считаются от всех записей
  периода. Строка записей без тегов видна только без выбранных категорий:
  такие записи не относятся ни к одной категории. Категории идут в том же
  порядке, что и вкладки выбора тегов.
- Пресеты в боковой панели — сохранённые наборы фильтров с названием. Пресет
  создаётся из текущих фильтров ленты и включает их все; применение копирует его
  фильтры в ленту, дальнейшие изменения фильтров пресет не меняют. Применённый
  пресет подсвечен, пока фильтры ленты с ним совпадают. Фильтры пресета можно
  заменить текущими фильтрами ленты, порядок пресетов в панели задаётся вручную.
  Первый пункт панели — «Вся лента» без фильтров.
- Галерея «Вложения» показывает вложения записей, проходящих текущие фильтры,
  и вложения из чатов: фото и видео отдельно от файлов, от новых к старым.
  Из просмотра вложения можно перейти к его записи в ленте или к его чату.
- Фильтры по типу, тегу, актуальности, тексту и полям к чатам неприменимы:
  пока они активны, вложения и ссылки из чатов в галерее скрыты. Период
  действует на них по времени сообщения.
- Ссылки в тексте записей и сообщений чатов кликабельны. Галерея собирает их
  отдельной вкладкой «Ссылки» по тем же правилам, с переходом к записи или чату.

### Чаты

- Чат — переписка с ассистентом, у которого есть доступ ко всей ленте через
  инструменты: он читает записи по фильтрам, создаёт, правит и удаляет их.
  Чат нужен, чтобы анализировать записи, получать советы и поручать действия.
- Чат не входит в ленту: переписка не засоряет её, а ассистент работает
  с лентой целиком. Ценное из чата сохраняется в ленту записью со ссылкой на
  чат — ассистентом по просьбе или кнопкой на сообщении. Так выводы из чатов
  находятся теми же фильтрами, что и всё остальное.
- Ассистент ссылается в ответах на записи, которые создал, изменил или
  упомянул; ссылка открывает запись в ленте.
- Новый чат создаётся из боковой панели. Там же пункт «Чаты» открывает список
  всех чатов от новых к старым с поиском по названиям и тексту сообщений.
  Название чату даёт модель.
- Чат можно переименовать и удалить. Удаление стирает переписку и её
  вложения; записи, сохранённые из чата, остаются в ленте с пометкой
  «из удалённого чата», и подтверждение удаления о них предупреждает.
- В чате панель ввода отправляет сообщения ассистенту: вместо типа выбирается
  модель, вместо тегов — права ассистента. К сообщениям можно прикладывать
  вложения.
- Права ассистента задаются в каждом чате и меняются по ходу переписки:
  - только чтение;
  - с разрешения — каждое изменение и удаление ассистент запрашивает;
  - удаление с разрешения — изменения сразу, удаление по запросу;
  - полные права — без запросов.

  Новый чат начинается с режима «с разрешения».
- Ассистент работает через провайдера на выбор (API, совместимые с OpenAI или
  Anthropic) с ключом пользователя. Сообщения и записи, которые читает
  ассистент, уходят провайдеру.
- Провайдер, ключ и модели задаются на странице настроек; она открывается из
  боковой панели значком шестерёнки.
- Стартовая инструкция избавляет от того, чтобы в каждом чате заново
  объяснять правила типовой ситуации: учёта калорий, изучения английского.
  Она выбирается в новом чате до первого сообщения и потом не меняется — это
  начало чата, а не настройка, которая меняется по ходу переписки, как модель
  или права. Чат сохраняет её текст: правка инструкции действует на новые чаты,
  а в начатом новое правило можно просто написать. Быстрого старта чата с
  инструкцией из боковой панели нет — выбор в самом чате.
- Общая инструкция действует во всех чатах. Чат сохраняет тексты общей
  и стартовой инструкций с первого сообщения, поэтому любая правка инструкций
  действует на новые чаты: инструкции начатого чата не меняются.
- Ассистент знает общую и стартовые инструкции и по просьбе пользователя
  меняет или дополняет их; на это нужны те же права, что и на изменение
  записей.
- Стартовые инструкции и общая инструкция задаются на странице настроек.

## Открытые вопросы

- Мини-приложения: ассистент пишет приложение на HTML, которое работает
  в песочнице через те же операции, что и инструменты ассистента, — например,
  подсчёт калорий за день по записям еды. Следующий шаг после чатов.
- Синхронизация между устройствами.
